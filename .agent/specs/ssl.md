# SSL Specification

## Overview

Chauffeur provides local HTTPS via `mkcert`. One command generates browser-trusted SSL certificates for any project domain and its aliases.

---

## `chauf secure`

Enables SSL for the project in the current directory.

### Flags

| Flag | Description |
|------|-------------|
| `--project <path>` | Target a specific project by path |

### Flow

1. Resolve project slug from CWD or `--project`
2. Check mkcert is installed
3. Check mkcert CA is installed (`$(mkcert -CAROOT)` exists); if not, print install command
4. Collect all domains: primary + aliases
5. Generate SAN certificate covering all domains
6. Store cert/key at `~/.chauffeur/nginx/certs/<primary-domain>.{crt,key}`
7. Update project config: `ssl: true`
8. Regenerate nginx site config with SSL server block (HTTP→HTTPS redirect)
9. Reload nginx if running

### Output

```
✓ SSL enabled

  Certificate: ~/.chauffeur/nginx/certs/my-project.test.crt
  Domains:     my-project.test, admin.my-project.test
  Valid until: 2035-01-01

  Visit: https://my-project.test:8443
```

---

## `chauf unsecure`

Disables SSL for the project.

### Flow

1. Update project config: `ssl: false`
2. Regenerate nginx site config without SSL (HTTP only)
3. Reload nginx if running
4. Print note about cert files still existing (not removed)

---

## Certificate Storage

```
~/.chauffeur/nginx/certs/
├── my-project.test.crt          # SAN cert (covers all aliases)
├── my-project.test.key          # Private key
├── default.crt                  # Self-signed for catch-all block
└── default.key
```

**Naming**: Always the primary domain. Never alias names.

---

## SAN Certificates

When a project has aliases, a single SAN (Subject Alternative Name) certificate covers all domains:

```bash
# Generated by Chauffeur:
mkcert \
  -cert-file ~/.chauffeur/nginx/certs/my-project.test.crt \
  -key-file  ~/.chauffeur/nginx/certs/my-project.test.key \
  my-project.test                \
  admin.my-project.test          \
  api.my-project.test
```

---

## Certificate Regeneration

Certs are automatically regenerated when:
- Adding an alias to an SSL-enabled project (`chauf link --alias`)
- Removing an alias from an SSL-enabled project (`chauf unlink --alias`)

New cert overwrites the previous one with the same filename.

## Nginx SSL Config

```nginx
# HTTP redirect block
server {
    listen 8080;
    server_name my-project.test admin.my-project.test;
    return 301 https://$host:8443$request_uri;
}

# HTTPS block
server {
    listen 8443 ssl;
    http2 on;
    server_name my-project.test admin.my-project.test;

    ssl_certificate     {{ .WorkspaceRoot }}/nginx/certs/my-project.test.crt;
    ssl_certificate_key {{ .WorkspaceRoot }}/nginx/certs/my-project.test.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers off;

    root {{ .ProjectPath }}/public;
    # ... rest of config
}
```

## Default Catch-All SSL

The default catch-all server block needs a certificate to handle HTTPS requests gracefully:

```bash
# Generated during chauf init:
mkcert \
  -cert-file ~/.chauffeur/nginx/certs/default.crt \
  -key-file  ~/.chauffeur/nginx/certs/default.key \
  localhost 127.0.0.1
```

## `chauf doctor` SSL Checks

1. mkcert binary exists: `which mkcert`
2. mkcert CA is installed: `$(mkcert -CAROOT)` directory exists
3. For each SSL-enabled project:
   - Cert file exists
   - Key file exists
   - Cert covers all current aliases (SAN check via `openssl x509 -text`)
   - Cert not expired (check `Not After`)
   - Cert matches key: compare modulus fingerprints
4. Default catch-all cert exists

## File Permissions

Set explicitly after cert generation:

| File | Permissions | Reason |
|------|-------------|--------|
| `*.crt` | `0644` | nginx needs to read |
| `*.key` | `0600` | Private key, owner only |
